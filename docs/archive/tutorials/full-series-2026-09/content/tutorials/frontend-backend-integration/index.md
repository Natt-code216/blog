# 前后端联调与数据加载状态

前端开发的"数据请求"看起来是一个 API 调用。实际上它涉及：

- **环境配置**：本地、测试、生产环境分别指向不同后端；
- **错误兜底**：网络错误、HTTP 错误、业务错误三层处理；
- **状态完整性**：loading / error / empty / success 至少四种状态；
- **缓存策略**：什么时候用缓存、什么时候重新拉取；
- **并发去重**：多个组件同时请求同一份数据时合并；
- **取消**：用户切换页面时取消正在进行的请求；
- **乐观更新**：让 UI 立即响应、后台异步同步；
- **重试**：网络抖动时自动重试，但不要无限重试。

每一项做对都不复杂，但只做对其中几项的项目就会让用户体验"差那么一点"。本系列把这些细节系统化。

## 4 章规划

1. **环境变量与 Service 层** —— API client 怎么抽象、env 怎么管理。
2. **加载 / 错误 / 空 三态** —— UI 完整性的最低要求。
3. **缓存、并发与取消** —— Server State 的运行机制。
4. **乐观更新与重试** —— 高级交互的两个高频模式。

## 阅读门槛

- 至少写过半年 React 项目；
- 用过 fetch 或 axios；
- 至少接触过一种数据请求库（SWR / TanStack Query / Apollo）。

不要求精通任何一种。
