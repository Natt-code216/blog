# 色彩与对比度

这一章我们讨论一个看似浪漫、实际严苛的领域：**颜色**。

浪漫的部分是色彩学——色相、饱和度、明度。严苛的部分是对比度——WCAG AA/AAA、视障用户、户外强光下还能不能看见。本章把这两部分结合在一起，给出一份能直接落地的色彩系统。

## 一个常见的错误：从几个"主色"开始设计

新人做色彩系统，第一反应是选几个主色——"我们的品牌色是 #4A90E2"。然后页面上到处用这个 #4A90E2。

这种做法的问题是：一个 UI 真正用到颜色的地方，**90% 不是品牌色**。是灰色——背景的灰、边框的灰、次要文本的灰、禁用状态的灰、阴影的灰。品牌色只在按钮、链接、强调标签这些不到 10% 的场景里出现。

所以一份成熟的色彩系统，**先做灰阶系统，再做品牌色**。

## 灰阶系统：至少 10 阶

灰阶不是 "灰一" "灰二" 这种笼统说法。它应该是一组明确的阶梯，从最浅到最深至少 10 阶。我习惯用 Tailwind 的命名风格：

```css
:root {
  --gray-50:  #fafafa;
  --gray-100: #f5f5f5;
  --gray-200: #e5e5e5;
  --gray-300: #d4d4d4;
  --gray-400: #a3a3a3;
  --gray-500: #737373;
  --gray-600: #525252;
  --gray-700: #404040;
  --gray-800: #262626;
  --gray-900: #171717;
  --gray-950: #0a0a0a;
}
```

这套灰阶在 HSL 空间里是均匀分布的，从 98% L 到 4% L。每一阶的对比关系都是稳定可预期的——例如 `--gray-700` 文本在 `--gray-50` 背景上的对比度是固定的（约 11:1），任何项目都可以直接复用这种关系，不需要再算。

具体到使用上：
- 主文本：`--gray-900` (浅色模式) / `--gray-50` (暗色模式)
- 次要文本：`--gray-600` / `--gray-400`
- 边框：`--gray-200` / `--gray-700`
- 背景：`--gray-50` / `--gray-900`

光是把这套灰阶系统建立起来，一个项目的 90% 颜色问题就已经解决了。

## 品牌色：克制使用

品牌色是用来"提醒"的，不是用来"装饰"的。任何用品牌色装饰的地方，本质上都是在抢用户的注意力。

我倾向于这样限制品牌色的使用场景：

1. 主操作按钮（每个页面通常只有 1–2 个）；
2. 链接（少量、明显的可点击文本）；
3. 当前选中的导航项；
4. 关键数据强调（如"利润 + 12%" 中的 + 12% 部分）；
5. 品牌 logo。

**警惕**：图表里所有色块都用品牌色变体，是一种常见的反模式。图表应该用一组互不冲突的色板（如 d3 color schemes），而不是品牌色的不同明度。

## 对比度：不是审美，是法规

WCAG 是网页可访问性的国际标准。它对色彩对比度的要求有两档：

- **AA**：正常文本对比度 ≥ 4.5:1，大文本（≥18.66px）≥ 3:1
- **AAA**：正常文本 ≥ 7:1，大文本 ≥ 4.5:1

很多国家（包括欧盟、美国政府机构）已经把 AA 列为政府类网站的法定要求。私营产品不一定强制，但如果你的产品有任何 B 端、医疗、教育用户，AA 几乎是必须的。

更现实的理由：低对比度文本在**强光下的手机屏幕**上根本看不见。无论用户的视力是否完美，AA 都是基本的体验底线。

实操层面：

```js
// 一段计算对比度的工具
function luminance(r, g, b) {
  const lin = v => {
    v /= 255;
    return v <= 0.03928 ? v / 12.92 : Math.pow((v + 0.055) / 1.055, 2.4);
  };
  return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b);
}

function contrast(rgb1, rgb2) {
  const l1 = luminance(...rgb1);
  const l2 = luminance(...rgb2);
  const [hi, lo] = l1 > l2 ? [l1, l2] : [l2, l1];
  return (hi + 0.05) / (lo + 0.05);
}
```

把这段函数挂到色彩面板里，让设计师 / 开发者每次选色时都看到对比度评分。一个团队养成"看对比度"的习惯之后，可访问性问题会自然消失。

## 警惕：颜色不应该是唯一的信息载体

WCAG 的另一条规则是：**颜色不应该是唯一的信息载体**。

经典反例：表单里的错误用红色边框标出。色盲用户（占人口约 8%）看不到那个红色。

正确做法：除了颜色变化，再加一个图标 / 文字提示。

```tsx
<input className={hasError ? 'border-red-500' : 'border-gray-300'} />
{hasError && (
  <p className="text-red-500 text-sm">
    <Icon name="alert-circle" /> 请输入有效的邮箱地址
  </p>
)}
```

注意"⚠️ 图标 + 文字提示"是冗余的。颜色只是这个冗余的一部分，不是唯一。

## 状态色：四种就够

UI 里反复出现的状态色，其实只有四种：

- **success**：绿色系（操作成功、可继续）
- **warning**：黄色系（注意，需要确认）
- **error / danger**：红色系（操作失败、不可恢复）
- **info**：蓝色系（中性提示）

```css
:root {
  --success-500: #22c55e;
  --warning-500: #f59e0b;
  --error-500:   #ef4444;
  --info-500:    #3b82f6;
}
```

每种再做 3 阶（50 浅背景、500 主色、700 深文字），合计 12 个状态色。任何"再加一种紫色表示极端警告"的提案都应该被打回——状态色越多，用户辨认的负担越重。

## 暗色模式不是"反色"

这一点专门留到第 5 章讨论，但本章先抛一个引子——把白底黑字的页面直接反色变成黑底白字，几乎一定会失败。

原因有三：
1. 纯黑（#000）背景反而比深灰（#171717）刺眼；
2. 浅色模式下的次要色（如 #999）在暗色背景下对比度急剧下降；
3. 阴影 / 边框这类"明度调制"的元素在暗色模式下需要重新定义。

第 5 章会展开这件事。

## 本章小结

色彩系统的核心不是"挑漂亮的颜色"，是"建立一组可预期的关系"。灰阶 10 阶 + 品牌色克制使用 + 状态色 4 类 + 对比度 4.5:1 兜底 —— 这套组合放在任何项目里都不会出错。

下一章我们讨论同样基础但同样常被低估的话题：**留白与节奏**。它决定了一张页面"会不会让人想停下来"。

## 一个补充：色彩的"温度"

最后再补一个看起来玄、但落地很简单的概念：色温。

每一个灰阶其实都可以是"冷灰"或"暖灰"。完全的中性灰（HSL 中 S=0）在大块面积上会显得"冷"和"工业感"；稍微加一点暖色（H 偏向 30 度，S 加到 3–5%），整张页面会显得"温和"。

```css
/* 中性灰 */
--gray-50: #fafafa;

/* 暖灰：稍微偏黄 */
--gray-50-warm: #fafaf7;
```

差别非常微妙，但放在 100 平的网页背景上能感受到。多数博客 / 阅读类网站会偏暖灰一点点；后台管理工具会保持中性灰；某些科技类品牌会刻意偏冷灰。这是一种品味选择，不是对错。但既然要做，至少应该意识到这件事。
