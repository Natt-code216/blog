# 字重·行高·度量

一个网页给人留下的第一印象，是它的文字。不是文字内容，是文字本身——大小、粗细、行距、间距。这些东西在视觉上几乎不占空间，但它们决定了用户在第一秒能否专注地读下去。

本章把排版拆成三个最基础的维度：字重、行高、度量。每一项做对了，可读性会提升一截；三项都做对了，整个页面看起来就"不像业余作品"。

## 字重：不是越多越好

新手最常犯的错误，是给一个项目同时引入太多字重——thin / light / regular / medium / semibold / bold / black 一应俱全，号称"灵活"。

实际效果是：每个区块的字重都不一样，整张页面看起来嘈杂。读者的眼睛找不到稳定的节奏。

**经验法则：一个网页最多用 3 个字重**。

一份保守的选择是 400 / 600 / 700——分别对应正文、强调、标题。再多反而是负担。

```css
:root {
  --fw-body: 400;
  --fw-emphasis: 600;
  --fw-heading: 700;
}
```

对中文还要额外注意一件事：中文字体对字重的支持普遍比英文差。"思源黑体"是为数不多能提供 7 个字重的中文字体；很多中文 web 字体只有 2–3 个字重可用。所以中文项目尤其要克制字重数量——很可能你想要的 light 在用户机器上根本不存在，被浏览器降级渲染成 regular，造成"我看 Figma 是细体，到了页面变成普通体"的常见困扰。

## 行高：决定文字"会不会读"

行高（line-height）的作用比字重还大，但被低估的程度也最深。

英文里有一句行话：行高决定了文字"会不会读"。太紧，段落像一堵密不透风的墙，读者扫两行就放弃；太松，眼睛在行间跳跃太远，丢失上下文。

**经验法则**：

- 正文：1.6–1.8（中文偏 1.7–1.8，英文偏 1.5–1.6）
- 大标题：1.1–1.3
- 小标签 / UI 文本：1.4–1.5

中文比英文需要更松的行高，原因是中文字符的"视觉密度"高得多——同样的行高数值，中文看起来比英文挤。

```css
:root {
  --lh-body: 1.7;
  --lh-tight: 1.25;
  --lh-ui: 1.4;
}

body { line-height: var(--lh-body); }
h1, h2 { line-height: var(--lh-tight); }
button, label { line-height: var(--lh-ui); }
```

我特别想强调一点：**行高永远用比例值，不用 px**。因为行高如果写死成 px，字号变化时它不跟着变，结果会出现"小字行高太大、大字行高太挤"的反直觉问题。

## 度量：屏幕上的"舒适视距"

度量（measure）是排版学里一个不常被提的术语，指**一行文字的字符数**。它直接影响阅读节奏。

太短（少于 40 字符）：眼睛要频繁换行，读起来累；
太长（多于 90 字符）：眼睛从行末回到下一行起点时容易"跳错行"，丢失上下文。

**经验法则**：

- 正文最佳：50–80 字符（中文等同于 25–40 字）
- 上限：90 字符

在 CSS 里有一个很好用的单位 `ch`，等于当前字体里一个字符的宽度：

```css
.prose {
  max-width: 65ch;
  margin: 0 auto;
}
```

这一行 CSS 在视觉上比所有"max-width: 800px"加起来都管用。它直接保证了文字的可读视距。

我所见过的几乎所有"读起来很舒服"的博客，文字主区域宽度都被严格限制在 60–70 ch 之间。无论它们的设计师有没有意识到这个术语，这都是排版学几百年沉淀下来的经验。

## 字号的层级：用比例而非随意

有了字重、行高、度量之后，还有一个看似简单但常被搞错的事：字号层级。

很多团队的字号是"看着差不多就行"——14、16、20、24、30、40 七零八落。这种零散字号在小屏 / 大屏切换时会立刻露馅——某一组在桌面上看起来"刚好"，在手机上就显得"挤"或"散"。

更稳的做法是用**比例**而不是绝对值。常用的两组比例：

- **Major Third**：1.25 倍递增（12, 15, 19, 24, 30, 37）
- **Perfect Fourth**：1.333 倍递增（12, 16, 21, 28, 37, 50）

```css
:root {
  --fs-base: 16px;
  --fs-scale: 1.25;

  --fs-sm:   calc(var(--fs-base) / var(--fs-scale));    /* 12.8 */
  --fs-md:   var(--fs-base);                            /* 16   */
  --fs-lg:   calc(var(--fs-base) * var(--fs-scale));    /* 20   */
  --fs-xl:   calc(var(--fs-base) * pow(var(--fs-scale), 2)); /* 25 */
  --fs-2xl:  calc(var(--fs-base) * pow(var(--fs-scale), 3)); /* 31 */
}
```

注意：`pow()` 是较新的 CSS 函数，老浏览器不支持。实际项目里可以提前算好硬编码：

```css
:root {
  --fs-sm: 0.8rem;
  --fs-md: 1rem;
  --fs-lg: 1.25rem;
  --fs-xl: 1.563rem;
  --fs-2xl: 1.953rem;
  --fs-3xl: 2.441rem;
}
```

这种比例化的字号阶梯，让大屏 / 小屏切换时只需要调整 `--fs-base` 一个变量，其余字号自动跟随。这是排版"令牌化"的第一步——我们下一章会展开。

## 一段可运行的最小示例

把本章所有原则放在一起，最简的"可读排版"长这样：

```html
<style>
  :root {
    --fs-base: 16px;
    --lh-body: 1.7;
    --lh-tight: 1.25;
    --fw-body: 400;
    --fw-heading: 700;
    --max-measure: 65ch;
  }

  body {
    font-family: 'Inter', system-ui, sans-serif;
    font-size: var(--fs-base);
    line-height: var(--lh-body);
    font-weight: var(--fw-body);
    color: #1a1a1a;
  }

  .prose {
    max-width: var(--max-measure);
    margin: 0 auto;
    padding: 2rem 1.5rem;
  }

  h1, h2, h3 {
    font-weight: var(--fw-heading);
    line-height: var(--lh-tight);
  }
</style>

<article class="prose">
  <h1>排版的三件套</h1>
  <p>本文从字重、行高、度量三个维度，把一个网页的可读性基础打牢……</p>
</article>
```

这一段不超过 30 行，但它涵盖了 80% 的"基础排版可读性"。如果一个项目只能做对一件事，应该是这件。下一章我们处理另一个高频痛点——色彩。

## 一个常被忽视的细节：字间距

中文排版里有一件英文世界几乎不需要考虑、但中文一直存在的问题——**字符间距**。

中文是方块字，每个字符宽度几乎相同。当字号偏大（≥20px）时，字符与字符之间会显得过分紧凑，整段读起来有"沉重感"。这种时候应该手工开一点字间距：

```css
h1, h2 { letter-spacing: 0.02em; }   /* 2% 字宽，足以"打开"标题 */
body  { letter-spacing: 0;     }     /* 正文不要加，加了反而散 */
```

但要注意：英文 letter-spacing 加大会让单词散开（每个字母之间都被推远），通常不需要。所以更精细的做法是只对中文文本加这个属性——可以用 `:lang(zh)` 选择器，或者按区块手工加 class。

字间距虽小，但在大标题这种"占据视觉焦点"的位置，做对和不做对的差别非常明显。这是中文排版工程里少数能用 CSS 一行解决、收益却很可观的细节。
