状态：本地首版已落地。更新日期：2026-09-30。

2026-09-30 增补：私藏网站加入「准Offer · OfferReady」，当前清单为 4 个网站。下文提到的 3 个网站保留首版规划记录；实际数量以 `src/services/collectionCatalog.ts` 为准。

以下保留设计依据与扩展方向；具体首版范围以上述实现记录为准。

## 1. 归类建议

新增一个轻量的「收藏」模块，页面展示标题建议为「值得反复打开」，内部包含「值得一读」与「私藏网站」。

现有教程区标题是「系统化学习」，内容按技术教程与章节组织；工具集主导航进入可操作的小工具目录。此次文章包含认知、人生、写作与关系等主题，收藏的网站也未必是单一工具。单独的收藏模块可以统一表达个人精选，同时让教程与工具集保留清晰的用途。

| 方案 | 优点 | 局限 | 建议 |
| --- | --- | --- | --- |
| 阅读放教程，网站放工具集 | 复用已有栏目，入口数量少 | 一份收藏被拆开；泛阅读容易被误认为技术课程，网站容易被误认为本站工具 | 作为关联入口，不作为主归属 |
| 全部放教程 | 学习相关内容集中 | 网站不一定属于学习路径，教程列表的层级变复杂 | 不采用 |
| 全部放工具集 | 现有工具推荐区可以容纳外链 | 人文阅读与工具的语义距离较远 | 不采用 |
| 独立「收藏」，关联教程与工具集 | 归属清楚，能呈现个人挑选的价值，方便继续扩充 | 需要新增一个页面与导航入口 | 推荐 |

「收藏」表示站主整理的公共清单，首版不引入访客账号、个人收藏夹或同步功能。

## 2. 页面与入口

### 主导航

建议顺序：`首页 / 随笔 / 教程 / 收藏 / 工具集`。

「收藏」默认进入 `/collection?view=reading`；直接打开 `/collection` 时也显示「值得一读」。无效的 `view` 值回到默认视图。视图切换同步到地址，浏览器刷新、返回与分享链接时保持一致。

| 入口 | 目标 | 页面状态 |
| --- | --- | --- |
| 主导航「收藏」 | `/collection?view=reading` | 值得一读 |
| 首页「值得一读」主卡 | `/collection?view=reading` | 值得一读 |
| 首页「私藏网站」副卡 | `/collection?view=sites` | 私藏网站 |
| 教程区关联入口 | `/collection?view=reading` | 值得一读 |
| 工具集关联入口 | `/collection?view=sites` | 私藏网站 |

保留现有主导航「工具集」进入工具目录的约定，不把它改为收藏页。

### 首页紧凑双入口

放在教程之后、工具集之前，作为一段有留白的横向双卡区域。阅读卡略宽，网站卡略窄；手机上按顺序纵向排列。首页以入口和少量视觉线索呈现收藏，不将全部 15 张内容卡铺开。

- 阅读入口：`值得一读 / 12 篇精选`，建议文案「读一点，想远一点」，配三张轻微错开的书签纸片。
- 网站入口：`私藏网站 / 3 个收藏`，建议文案「我的互联网书签」，配小型窗口或书签抽象图形。
- 两张卡均整卡可点击，文字、数量与箭头常显，不依赖悬停才看得到。
- 数量由同一份内容清单计算，不在不同入口手工维护。

教程区底部增加轻量文字入口「换一种方式学习 → 值得一读」；工具区底部增加「看看我常逛的网站 →」。两处只建立关联，不重复展示整套卡片。

### 独立收藏页

页头包含标题「值得反复打开」、一句说明「一些启发过我的文章，和愿意再次打开的网站」，以及「值得一读 12 / 私藏网站 3」两项切换。

阅读视图提供「全部」及六个主题筛选。桌面默认三列卡片，平板两列，手机一列；短屏上允许筛选标签换行，避免把最后一个主题藏起来。切换主题后清楚显示结果数量，提供返回「全部」的入口。

网站视图只有三个条目，首版全部展示，不再添加空泛的二级分类。

## 3. 卡片内容与跳转

### 阅读卡片

信息顺序：主题标签 → 中文参考译名 → 英文原题 → 作者 → 一句推荐理由 →「阅读原文 ↗」。中文标题为主要识别信息，英文题名完整保留，作者与外部来源清楚可见。

用户给出的中文内容是参考译名，不能标为「中文译文」或暗示本站已有全文翻译。首版只链接原文，不生成空的详情页。推荐理由在阅读或核对来源后另行撰写，当前规划不把未经核实的概括当作原文结论。

整张卡使用真实外链；建议在新标签页打开并提供相应提示，保留用户在收藏页的筛选位置。无论如何选择打开方式，都应保持三处入口和卡片的一致行为。键盘焦点与点击区域清楚，卡内不嵌套相互冲突的按钮。

### 网站卡片

信息顺序：经核对的站名 → 域名 → 经核对的一句用途 →「访问网站 ↗」。站名或用途未核实时，先使用域名，不凭域名推断功能，也不放临时编造的描述。

图标可采用简洁的字母或几何标识；首版不依赖第三方截图服务。`9eip.com` 的目标地址必须保留用户提供的 `#term-80223` 锚点。

## 5. 视觉与交互

延续现有深浅主题、细边框、大留白与衬线中文标题。阅读卡用现有教程的淡紫色作点缀，网站卡用工具区的浅绿色；避免再引入大面积的新颜色。首页现有星球已经提供持续动态视觉，新区域以用户操作触发的短动效为主。

| 场景 | 交互建议 | 约束 |
| --- | --- | --- |
| 首页阅读入口悬停 | 三张书签纸片略微展开，箭头向右上移动 | 卡片文字始终清楚；不改变点击目标 |
| 独立页卡片悬停或聚焦 | 卡片抬升约 3–4px，边框渐亮 | 聚焦状态明确；不依赖鼠标才显示内容 |
| 切换视图与主题 | 选中底色平滑切换，结果短暂淡入 | 建议 180–240ms；不播放长时间重排动画 |
| 首次进入可见区域 | 卡片短距离淡入 | 只触发一次，避免反复滚动造成闪烁 |
| 外链交互 | 标准链接、可复制目标、可键盘激活 | 显示外部跳转标识和新标签提示 |

移动端将双入口纵排、阅读卡单列，触摸区域留足空间；不要求悬停，不使用翻面才能看到内容的卡片。主导航增加第五项后，需同步调整窄屏间距或折叠菜单，保证 320px 宽度下仍能访问全部入口。

遵守 `prefers-reduced-motion`：取消纸片展开、抬升和位移动画，改为直接切换或静态边框反馈。保留全部内容、焦点提示与功能。深浅主题均需检查文字和边框对比度。

## 6. 单一内容来源

规划采用一份收藏清单存储全部条目，不分别写进教程数据、工具数据、首页数据与搜索数据。每条记录有稳定标识和类型：`reading` 或 `site`。

阅读条目保存主题、英文原题、中文参考译名、作者、原始 URL，以及后续核对后的推荐理由；网站条目保存原始 URL、核对后的站名和用途。需要调整显示标题时，可单独保存显示字段，原始资料仍可追溯。

首页双入口、收藏页、教程与工具区关联入口以及搜索索引，都引用这份来源。数量自动计算。后续若转为 CMS 管理，应迁移同一份清单，不长期维护静态文件与 CMS 两套独立数据。

## 7. 最小落地范围与后续选项

### 首版最小范围

1. 核对 12 篇文章的题名与可访问目标、3 个网站的展示名及用途，补充简洁的推荐理由。
2. 一份收藏数据，两个内容类型，六个阅读主题。
3. `/collection?view=reading` 与 `/collection?view=sites` 两个可分享视图，以及主题筛选。
4. 顶部「收藏」、首页紧凑双入口、教程和工具区各一条关联入口。
5. 完整的 12 张阅读卡和 3 张网站卡，外链语义和展示说明一致。
6. 将收藏纳入已有全站搜索，支持中文标题、英文标题、作者和主题检索，标记「阅读」或「网站」。
7. 少量悬停与切换动效，手机布局、键盘访问、深浅主题与减少动态支持。

验收重点：入口目标一致，刷新与返回恢复所选视图，六类筛选各对应两篇文章，文章总数 12、网站总数 3，无重复记录，9eip 锚点完整，窄屏导航可用。动画通过 `prefers-reduced-motion` 关闭，纸片悬停展开仅在支持悬停且允许动态时启用。

### 后续可选

- 「随便读一篇」：抽出一张推荐卡，读者确认后再跳转原文。
- 「已读」与「稍后读」：需求明确后再增加本机状态，并说明保存范围。
- 独立页内搜索：收藏增长后添加，首版优先复用全站搜索。
- CMS 编辑、链接定期核查、更多收藏类型：在实际维护量增长后再扩展。
