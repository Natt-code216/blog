# 工具集跳转规则与修复记录

## 排查结论

- 首页和文章页的“工具集”原来指向首页 `#tools`，工具页的同名导航却指向完整目录。
- 开发服务器直接打开 `/mini-tools` 会回退到 React 主站，原路由未处理这个目录地址，显示 404。
- 目录搜索只保存在输入框中，进入工具后点“返回工具集”会清空筛选。
- 从目录返回 `/#tools` 时，滚动只执行一次；前面的随笔、教程异步加载完成后会改变工具区的位置。
- 11 个工具的 HTML 入口和原有卡片链接本身有效，不需要把工具改成 React 页面。

## 修复后的跳转约定

| 入口 | 目标与行为 |
| --- | --- |
| 全站主导航“工具集”、首页工具箱卡片 | 整页打开 `/mini-tools/index.html` |
| 首页单个工具卡片、快捷入口、全站搜索结果 | 整页打开对应 `/mini-tools/<name>.html` |
| 直接打开 `/mini-tools` | React 回退路由使用 `location.replace` 打开目录，保留查询参数与锚点，不增加无用的历史记录 |
| `/mini-tools/` | 由静态服务器读取目录的 `index.html` |
| 目录搜索 | 在当前历史项保存 `?q=关键词`，刷新与浏览器返回时可恢复 |
| 筛选后的目录 → 单个工具 → “返回工具集” | 工具链接携带 `q`，返回同一个筛选后的目录 |
| 直接打开单个工具 → “返回工具集” | 返回未筛选的完整目录 |
| 工具页主导航“工具集”、页脚“全部工具” | 打开未筛选的完整目录 |
| 目录“返回首页工具区”、首页“创造者” | 保留 `/#tools` 定位行为 |

工具的返回目标固定为本站目录，只传递经过 URL 编码的搜索词，不接受任意返回地址。工具处理逻辑不读取该搜索参数。

首页的随笔、教程栏目使用 `aria-busy` 表示加载状态。锚点定位先立即执行，仅在目标之前仍有加载中的栏目时临时观察 DOM，全部完成后再校正一次并停止。路由切换、卸载、用户滚轮、触摸、指针或滚动按键操作都会取消待执行校正，避免打断后续操作。

## 验收

- 自动回归覆盖：首页和文章页的整页导航、目录筛选与清空、中文及特殊字符编码、未匹配查询、延迟加载后的定位、手动操作取消、路由切换清理、减少动画偏好与无效锚点。
- 生产预览逐一打开 11 个工具，确认标题、地址、返回链接各自正确。
- 生产预览验证筛选后进入 PDF 工具并返回、刷新、浏览器前进后退、目录地址兼容和返回首页工具区。
- 类型检查、全站测试、生产构建和 13 个 HTML 入口及其资源校验均通过。

本次验收在本地开发与生产预览环境完成，未发布线上部署。
