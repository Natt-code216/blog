# 第一章 · 把前端、后端和内容一起交付

本地能打开网页，只说明你这台电脑上的服务齐全。上线时最容易遗漏的是：前端静态文件已经发布，但 API 仍指向 localhost；后端已经启动，却没有数据库中的内容；详情能点击进入，却不能刷新。

**本章完成标志**：能生成并本地验收生产构建，列清线上配置，并按检查表验证一次发布。本章不会替你创建收费资源或承诺某个平台永久免费。预计阅读与本地操作 40 分钟，云端配置时间取决于所用服务。

### 1. 先画清楚请求关系

```text
读者浏览器
  ├─ 下载静态前端：HTML / CSS / JavaScript / 工具页面
  └─ 请求内容 API：HTTPS → Strapi → 数据库
                                  └─ 媒体文件存储
```

前端的 `dist/` 可以放在静态托管上；Strapi 需要持续运行的 Node.js 进程。文章存储在数据库中，上传图片在独立存储中；Git 仓库只保存代码与稿件，不会自动包含这两部分运行数据。

沿用本仓库的 Node.js 24。云端若默认使用不同版本，显式设置构建和运行版本，并以当前锁文件及后端 `engines` 范围为准。通用启动流程参考 [Strapi 部署文档](https://docs.strapi.io/cms/deployment)。

### 2. 先在本地确认构建没有问题

在仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test:run
pnpm build
pnpm preview
```

本站 `build` 不只生成首页，还会构建 `mini-tools/` 多页面入口，并检查关键产物。打开 preview 输出的地址，确认首页、教程详情以及 `/mini-tools/json-formatter.html` 都能加载。

如果此时仍连接本地 API，浏览器的请求来源会从开发端口变成预览端口。需要将实际预览来源加入本地 CORS，或者在配置允许的同一来源下验收；不要把这个差异误诊为生产代码失效。

### 3. 准备可持久化的后端

先部署后端，再让前端引用它的正式 API 地址。托管服务的应用根目录设为 `backend/`；安装、构建、启动分别对应：

```bash
npm ci
NODE_ENV=production npm run build
NODE_ENV=production npm run start
```

这些是从 `backend/` 工作目录执行的类 Unix 命令。不要在生产中使用 `develop`，它为开发热重载设计。确保构建阶段可安装开发依赖，生产构建完成后再按平台规则裁剪运行依赖。

数据库以 PostgreSQL 为例：本仓库目前只安装 SQLite 驱动，切换前需在开发环境执行并提交更新后的后端依赖和锁文件：

```bash
npm install pg --prefix backend
```

在部署平台配置 `DATABASE_CLIENT=postgres`、数据库连接信息或 `DATABASE_URL`，以及主机要求的 SSL 参数。现有 `backend/config/database.ts` 已列出对应配置入口。是否需要 CA 证书和 SSL 由数据库提供方决定，不要为绕过连接报错统一关闭证书校验。参数含义参考 [Strapi 数据库配置](https://docs.strapi.io/cms/configurations/database)。

SQLite 依赖磁盘文件，在有持久卷、备份和明确单实例约束的环境也可使用；临时容器磁盘不适合保存它。本系列以持久化 PostgreSQL 为部署练习方案，不能把它理解成安装 Strapi 的唯一数据库选择。

上传文件同样要持久化。使用对象存储时，按选定提供方安装上传 provider 并配置；不上传图片的首轮文本教程验收可以先跳过，但不能假设容器重建后本地上传文件仍在。

### 4. 逐项填写线上配置

| 位置 | 配置 | 验证方式 |
| --- | --- | --- |
| 后端 | `HOST=0.0.0.0`、平台分配的 `PORT` | 平台能访问应用端口 |
| 后端 | 生产专用密钥，名称参考 `.env.example` | 能正常启动和登录管理后台 |
| 后端 | 数据库连接与持久存储 | 重启后已有文章仍存在 |
| 后端 | `backend/config/middlewares.ts` 的 CORS | 允许正式前端的完整 origin |
| 前端构建环境 | `VITE_API_URL=https://你的内容域名/api` | Network 请求指向正式 HTTPS API |
| 内容后台 | Public 读取权限和 Publish | 匿名访问能读到教程正文 |

`origin` 包含协议、域名以及非默认端口，不带页面路径。本站当前 CORS 只列了本地开发地址，发布前要加入你自己的前端域名。若页面是 HTTPS，API 也要使用 HTTPS，避免浏览器拒绝混合内容。

前端环境变量在构建时进入产物，配置变化后重新构建。[Vite 环境变量说明](https://v5.vite.dev/guide/env-and-mode)也解释了为什么不能把数据库密码写入 `VITE_` 变量。

### 5. 部署静态前端，并验证深层地址

以仓库现有的 Vercel 配置为例，项目根目录选仓库根，安装命令为 `pnpm install --frozen-lockfile`，构建命令为 `pnpm build`，产物目录为 `dist`。这些字段已在 `vercel.json` 中记录，另需在平台设置前端 API 环境变量。

该文件还配置了将前端路由交给 `index.html` 的 rewrite。回退应服务 `/tutorials/...` 这类 SPA 路由，同时确认真实的 JS、CSS 和工具 HTML 仍以正确内容类型返回。规则概念参考 [Vercel Rewrites](https://vercel.com/docs/routing/rewrites)，其他托管平台也需要完成相同的路径处理。

至少直接打开并刷新三种地址：首页、一个教程详情、一个工具 HTML。检查 Network：JavaScript 请求不能返回 `text/html`，工具页应显示工具界面而不是博客首页。不要只通过首页点击来判断路由部署成功。

### 6. 单独处理内容迁移

`pnpm tutorials:sync` 是本地 SQLite 同步命令，故意不接受远程数据库。把代码部署成功不会自动让线上出现五篇教程。

第一次上线可以在后台按对应 slug 手动建立并发布内容；已有线上库时，应先备份并在测试环境演练 Strapi 的导出、导入或传输流程，再选择需要的迁移范围。不要把本地 SQLite 文件覆盖到一个正在使用的 PostgreSQL 服务上。内容迁移与代码部署分开验收，才能知道缺失内容究竟发生在哪一层。

### 7. 发布验收与回退

| 验收项 | 通过条件 |
| --- | --- |
| 首页教程 | 五个主题，React 为 3 章，其余各 1 章 |
| 正文与目录 | 每个入口对应自己的内容，目录定位正确 |
| 匿名读取 | 无管理账号登录也能读取已发布教程 |
| 详情刷新 | 直接访问深层 URL 能打开正确页面 |
| 工具与静态资源 | 工具页可用，脚本响应不是 HTML |
| 后端重启 | 文章仍存在，图片链接按所选存储方案可访问 |
| 故障提示 | API 不可用时能看到错误与重试 |

发生问题时先保留当前错误信息：构建失败看构建日志；502 或进程退出看后端日志；403 看读取权限；200 空数组看发布状态；浏览器 CORS 错误看 origin；仅刷新 404 看前端回退规则。

记录这次上线使用的代码提交、环境变量名称和数据库备份位置。前端可以恢复上一个构建版本；涉及 schema 或数据迁移时，回退代码不一定能回退数据库，需要事先验证备份恢复步骤。

### 本章练习与后续

先在本地完成 `pnpm build` 和预览，把上表逐项标记为「已验证」或「待线上验证」，不要将还没实际部署的项目写成已上线。后续章节可进一步讲自动部署、监控和备份恢复演练。
