# 现代前端架构指南

写这个系列的契机，来自一个被我反复目睹的状态：一个项目从两人小组开始，做到第三年、五个人、十万行代码，然后所有人都开始抱怨"这个项目越来越难改了"。新需求落地变慢、bug 排查变长、新人上手要两周才敢提第一个 PR。但奇怪的是，每一处单独看都还可以——没有谁写了特别差的代码。问题出在**结构**里。

这就是"前端架构"真正想解决的问题。它不是一组炫技的模式集合，不是某个框架的"最佳实践"列表。它是一种长期成本意识——在每一次"先这样写"的小决定之前，问一句：三年之后还能这样写吗？

本系列从这个角度出发，分六章逐步展开。

## 章节索引

1. **为什么需要前端架构** —— 项目变大之后到底卡在哪里？给"需要架构"列一份可被观察到的症状清单。
2. **路由与目录组织** —— 从"按文件类型分类"转向"按业务领域切片"。
3. **状态分层与跨层通信** —— 把 server / ui / form 三种状态分开放，每一类用合适的工具。
4. **数据获取与缓存** —— TanStack Query 的心智模型，stale-while-revalidate 的实战考量。
5. **模块边界与代码分割** —— 按路由切包、动态导入、bundle 预算的合理设定。
6. **架构演进与重构信号** —— 看到哪些信号时该重构，看到哪些信号时反而该忍。

## 阅读前提

- 写过两年以上 React / Vue 项目的工程师；
- 至少负责过一次三千行以上模块的接手与重写；
- 对"组件应该长什么样"有自己的直觉但说不清楚为什么。

如果你完全是新手，本系列对你帮助有限——你应该先去把第一个项目跑起来；架构是项目变大之后才出现的问题。

## 关于代码示例

所有代码片段都以 TypeScript + React 为示意，但论点本身在 Vue / Svelte / SolidJS 中同样成立。涉及到具体工具（如 TanStack Query、Zustand）时会注明哪些是工具特性、哪些是通用原则。

读完本系列，你不会得到一份"架构图模板"，但你会得到一组观察项目健康度的指标，以及在每一个小决定上选边的依据。
