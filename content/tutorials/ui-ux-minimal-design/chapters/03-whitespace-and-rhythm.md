# 留白与节奏

新手设计的页面，最大的问题往往不是"颜色不好看"或"字号不对"，而是**到处太挤**。各元素紧贴着，没有呼吸的空间，整张页面像一个堆满杂物的房间——东西其实都不错，但你不想久留。

留白（whitespace）不是设计师"懒得填东西"，是它本身就是一种内容。本章讲怎样把留白系统化，让一份界面有节奏、有呼吸。

## 间距阶梯：少而稳

最常见的错误是间距随手填——这里 12px、那里 16px、再那里 20px。看起来都是"合理的小数字"，实际上每个数字都是一次"无依据的决定"。

正确做法是先建立一组间距阶梯，然后所有间距只能从这套阶梯里选。一种最常用的 4px 基线：

```css
:root {
  --space-1:  4px;
  --space-2:  8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 24px;
  --space-6: 32px;
  --space-7: 48px;
  --space-8: 64px;
  --space-9: 96px;
}
```

这九阶覆盖了 99% 的间距场景。从此以后，任何"我觉得这里应该再加点空"的冲动都必须转化成"用阶梯里的哪一阶"。

这种约束的好处是：

1. **一致性自动出现**——所有按钮的内边距都是 `--space-3 --space-4`，所有卡片的外边距都是 `--space-5`，看起来就有秩序。
2. **响应式简单**——大屏用 `--space-6`，小屏用 `--space-4`，调整时心智成本极低。
3. **审查简单**——PR 里如果看到 `padding: 17px`，立刻可以指出"这不是阶梯里的值"。

## 节奏：用 4 倍间距分组

光有阶梯还不够，还需要会**用**。一个常见的细节技巧叫"4 倍间距分组"：

- 紧密相关的元素之间：1 倍间距（如 label 和 input）
- 同组内的兄弟元素之间：2 倍间距（如表单内的几个字段）
- 不同组的元素之间：4 倍间距（如表单和表单后的按钮组）
- 整页板块之间：8 倍间距

```css
.form-group {
  display: flex;
  flex-direction: column;
  gap: var(--space-2);  /* label - input */
}
.form-stack {
  display: flex;
  flex-direction: column;
  gap: var(--space-5);  /* group - group */
}
.section {
  margin-bottom: var(--space-8); /* section - section */
}
```

这种"倍数关系"让眼睛能立刻识别"哪些是同一组、哪些是不同组"，无需文字说明。这是格式塔心理学里的"邻近原则"在 UI 里的实践。

## 卡片的内边距：经常错的小事

卡片是 UI 里出现频率最高的容器，但卡片内边距很多人写得不对。

错误一：上下左右都一样，比如 `padding: 16px`。这种 padding 会让内容居中地挤在卡片里，缺少节奏感。

错误二：内边距太小（< 16px）。视觉上整个卡片像一张"贴满标签的卡片"，没有呼吸空间。

正确做法：纵向略小于横向，整体不小于 24px。

```css
.card {
  padding: var(--space-5) var(--space-6); /* 24px 32px */
}
```

这种"纵向略小、横向略大"的搭配，与文字的自然阅读方向一致——眼睛从左到右扫描时左右留白带来的视觉缓冲更重要。

## 留白与信息密度：不是矛盾

有些团队会担心"留白多了 = 信息密度低"。这其实是个误解。留白的真正作用是让信息**层级**清晰，而不是减少信息量。

举个例子：一张数据看板上有 6 个 KPI 卡片。如果它们紧紧贴在一起，用户的眼睛会感觉"这是一团信息"；如果用 16–24px 的间距隔开，并把"主要 KPI"用稍大的卡片标出来，用户的眼睛会自然按顺序扫描——先看主 KPI，再看次 KPI。

信息量没变。但用户的认知成本被留白显著降低了。

## 全屏页面 vs 紧凑页面：两种节奏

设计要服务于场景。同一种"留白原则"在不同场景下要有不同尺度。

**全屏 / 营销型页面**（如产品官网首屏）：大留白。section 之间的间距可以达到 `--space-9`（96px）甚至更大。视觉冲击优先。

**生产力 / 后台型页面**（如管理后台、数据看板）：紧凑节奏。section 之间 `--space-5`（24px）即可。信息密度优先。

如果同一个项目里既有营销页又有后台页，建议这两种页面用**两套不同的间距密度**，但都基于同一个间距阶梯。这种做法既保持系统一致，又能适应不同场景。

## 边距 vs 内边距：何时用谁

`margin` 和 `padding` 的选择是很多人长期搞不清的事。一个简单的判断标准：

- **padding** = 元素**内部**到内容的距离 → 它是元素自己的属性；
- **margin** = 元素**外部**到周围元素的距离 → 它是元素与环境的关系。

经验法则：

- 卡片、按钮、标签内的内边距 → padding
- 卡片与卡片之间、章节与章节之间 → margin（或 gap）
- 容器里的子元素间距 → 用 `gap`，不用 margin

为什么用 gap 不用 margin？因为 margin 容易出现"塌缩"（margin collapse）的反直觉问题，且第一个子元素的上 margin、最后一个子元素的下 margin 都需要专门处理。gap 没有这些问题。

```css
/* 推荐 */
.stack { display: flex; flex-direction: column; gap: var(--space-4); }

/* 不推荐 */
.stack > * + * { margin-top: var(--space-4); } /* 老 trick */
```

## 本章小结

留白系统化的核心是：先建一组阶梯，再用倍数关系组合。任何"看起来需要再加一点空"的冲动，都要被阶梯收编。这种约束看起来束缚创造力，实际上恰恰相反——它把"每一处随手填数"的认知负担消除了，让真正需要思考的留给"用哪一阶"。

下一章我们把字号、灰阶、间距这三套阶梯合并成一个统一的概念：**设计令牌**。这是把视觉规范从 Figma 翻译到代码的桥梁。

## 一个常被忽视的小事：垂直对齐

最后补一个小细节。在多列布局里，相邻两列的"文字基线对不对齐"是非常容易被忽视、却严重影响整页质感的事。

例如一个标签列 + 数值列的简单结构：

```html
<div class="row">
  <span class="label">订单状态</span>
  <span class="value">已完成</span>
</div>
```

如果两个 span 的 line-height 不同（比如 label 设了 1.4、value 设了 1.6），它们的基线就会错开。在视觉上是 1–2px 的偏差，但放在二十行表格里看起来就像每一行都"歪了一点"。

解决方法很简单：在一个语义组内部，line-height 必须统一。一种保守做法是让所有 UI 文本统一用 `var(--lh-ui)`（如 1.4），只有正文章节才用 `var(--lh-body)`。这种统一带来的视觉整洁度比任何花哨的设计都更值得花心思。
